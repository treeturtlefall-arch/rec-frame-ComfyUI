## 1. 「上部のL字枠（X軸・横棒）が短く見える」現象について

### 現象の概要
ファインダー枠を合成した際、**「下部の枠は縦横均等に見えるのに、上部の枠はX軸（横棒）が短く、縦棒（Y軸）ばかりが長く見える」** という印象を受けることがあります。

### 結論（検証データ）
プログラムの描画エンジン上、**四隅すべてのL字枠は、X軸・Y軸ともに「1ピクセルの狂いもなく完全に等長（同一ピクセル数）」で描画されています。**

例（短辺832px、`arm_len_ratio=0.15` の場合）：
- **左上 (TL)**: 横棒 125 px / 縦棒 125 px
- **右上 (TR)**: 横棒 125 px / 縦棒 125 px
- **左下 (BL)**: 横棒 125 px / 縦棒 125 px
- **右下 (BR)**: 横棒 125 px / 縦棒 125 px

### なぜ短く見えてしまうのか？（視覚的メカニズム）

#### ① 内側要素（電池・RECインジケータ）との突き出し量の圧倒的格差
- **下部（特に左下）**: 周囲にUI要素が一切ない開放空間のため、角から伸びる横棒（125px）と縦棒（125px）の全体が視認でき、「縦横が等長」と自然に知覚されます。
- **上部（左上・右上）**:
  - L字枠の内側（すぐ横・下）に電池マークやREC文字（赤丸＋ラベル＋座布団）が配置されます。これらは**横に細長い長方形**です。
  - **左上（電池）**: 縦棒は電池の下端から **約 80px** も長く下へ突き出ていますが、横棒は電池の右端から **わずか約 20px** しか外側に突き出ていません。
  - **右上（REC）**: 赤丸＋REC文字はさらに横長なため、**REC座布団のほうが横棒の先端よりも約 25px 外側（左側）に突き抜けています**（横棒の先端がREC文字の途中で終わっているように見える）。
  - この「縦棒は豪快に突き出ているのに、横棒はUIとほぼ同等の長さしかない」という強い対比効果により、脳が**「横棒が短い」**と錯覚します。

#### ② 水平垂直錯視（Vertical-Horizontal Illusion）
心理物理学上、人間は物理的に全く同じ長さの水平線と垂直線を見た時、**垂直線（Y軸）のほうを約 10%〜20% 長く認識する**という生来の錯視特性を持っています。
これに上記のUI対比効果が加わることで、「上部の横棒が詰まって短い」という知覚が決定的なものになります。

## 2. ユーザーへの推奨調整ガイド（公開時の注意書き案）

もし上部枠の横棒の長さに詰まり感を感じたり、より力強いファインダー感を演出したい場合は、以下のパラメータ調整をおすすめします。

| パラメータ | 既定値 | 推奨設定 | 効果 |
|---|---|---|---|
| `arm_len_ratio` | `0.15` (15%) | **`0.18` 〜 `0.20`** (18〜20%) | 横棒がREC文字や電池マークの外側へしっかりと長く突き出るようになり、上部・下部ともに伸びやかなファインダー枠になります。 |
| `thickness` | `50` | `30` 〜 `50` | 枠の太さをやや細めに設定すると、線のシャープさが際立ち錯視の影響が和らぎます。 |
| `bg_box_opacity` | `0.0` (ワークフロー推奨 0.35) | `0.0` 〜 `0.20` | 座布団の不透明度を控えめにすることで、枠線との境界の対比コントラストが穏やかになります。 |

## 3. 将来の公開・README への記載メモ

GitHub や ComfyUI Manager で本カスタムノードを公開する際、FAQ セクションに以下のようなQ&Aを設けておくと親切です：

> **Q. 上部のL字枠が下部よりも短く見えます。不具合ですか？**
>
> **A. ピクセル単位で完全に同一の長さ（四隅すべて等長）で描画されています。**
> 上部には電池マークやRECインジケータ（横長のUI要素）が隣接しているため、錯視（対比効果・水平垂直錯視）によって横棒が短く感じられることがあります。
> もし横棒をもっと長く見せたい場合は、ノードの `arm_len_ratio`（既定 0.15）を **`0.18` 〜 `0.20`** に広げてご使用ください。

## 4. カスタムフォント・カスタムマーク（ドット画像）の追加方法と使い分け

ユーザーが好みのフォント（`.ttf`, `.otf`, `.ttc`）や自作のRECマーク・ロゴ画像（`.png`, `.webp`）を使用する方法として、本ノードは **「フォルダ配置方式」** と **「パス直接入力方式」** の2系統を用意しています。
将来の公式マニュアルや README では、それぞれのメリット・注意点を明記して案内します。

### 追加方法の比較まとめ

| 方式 | 設定場所 | メリット | 注意点・適した用途 |
|---|---|---|---|
| **方法A: フォルダ配置方式**<br>（恒常的・一覧選択） | フォント: `fonts/`<br>マーク: `assets/dots/` | ・ドロップダウン（`font_key` / `dot_style`）の選択肢に並び、簡単に切り替え可能<br>・ワークフロー共有時にパス切れを起こしにくい | ・ComfyUI起動中にファイルを追加した場合、**ComfyUIの再起動が必要**<br>・常用する定番素材向け |
| **方法B: パス直接入力方式**<br>（即座にお試し・個別利用） | ノード入力欄:<br>`custom_font_path`<br>`custom_dot_path` | ・**ComfyUIの再起動が不要**（パス入力で即座にプレビュー反映）<br>・ノードフォルダ内に素材をコピーせず外部フォルダから直接参照可能<br>・他ノードからの動的パス入力に対応 | ・ローカル絶対パス（`C:\Users\...` 等）を指定した場合、**他人にワークフローを共有するとパス切れ**になりデフォルトへフォールバックする<br>・一時的な試行錯誤や個人環境向け |

### 将来のマニュアル・README 向け記載文案

#### Q. 好きなフォントやオリジナルのRECマーク（透過画像）を使いたい

**A. 以下の2通りの使い方が可能です。用途に合わせて使い分けてください。**

1. **手軽に今すぐ試したい場合（再起動不要）**
   - ノード下部の `custom_font_path` または `custom_dot_path` に、お使いのPCにあるファイルのフルパス（例: `C:\Assets\MyFont.ttf` や `C:\Images\logo.png`）をコピペしてください。
   - ComfyUI を再起動することなく、貼り付けた瞬間にプレビューや生成結果へ即時反映されます。

2. **いつでもメニューから選べるようにしたい場合（定番登録）**
   - フォントファイルは本ノードの `fonts/` フォルダへ、マーク画像（透過PNG/WebP）は `assets/dots/` フォルダへ配置してください。
   - ComfyUI の再起動後、ノードのドロップダウンメニュー（`font_key` / `dot_style`）に自動登録され、いつでもリストから選択できるようになります。
   - 他の人にワークフローを共有する場合も、このフォルダ配置にしておくと相手の環境でパス切れを起こさず安全です。

#### Q. `fonts/` や `assets/dots/` にファイルを置いたのにドロップダウンに出てきません

**A. ComfyUI を再起動してください。**
ComfyUI の仕様上、ドロップダウンメニューの選択肢一覧は起動時に生成されます。配置後に ComfyUI を再起動することでリストへ反映されます。もし今すぐ再起動せずに使いたい場合は、上記「1. パス直接入力方式」をご利用ください。
